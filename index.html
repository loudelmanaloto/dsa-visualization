LIFO · Last in, first out

Stack

A stack only lets you touch the item on top. You add (push) and remove (pop) at the same end, so the last thing in is the first thing out, like a pile of plates.

How a stack works

      

        

          
A stack is a list with one rule: you can only add or remove at the top. That rule gives it LIFO order (last in, first out). The item you pushed most recently is always the next one to come off.

          
The demo above uses an array of fixed capacity 8 plus one integer, top, holding the index of the top item. An empty stack has top = -1. Push moves top up one and writes there. Pop reads data[top] and moves top down. Nothing else in the array ever moves, which is why every operation is constant time.

        

        

          
Two errors to know

          
    
            
  • Overflow: pushing when top == capacity - 1. A fixed array has no room left. Dynamic arrays (Python lists, Java ArrayList) avoid this by copying into a bigger array, which is still O(1) on average.
    • 
            
  • Underflow: popping or peeking when top == -1. Always check isEmpty() first.
    • 
          

          
A stack can also be built from a linked list: push inserts a new head node, pop removes the head. No capacity limit, but each node costs extra memory for its pointer.

Where stacks show up

      

        
    
          
  • The call stack. Every function call pushes a frame (its local variables and return address); returning pops it. Infinite recursion fills it up, which is literally a stack overflow.
    • 
          
  • Undo / redo in editors, and the Back button in a browser.
    • 
          
  • Bracket matching in compilers and code editors (the demo above).
    • 
        

        
    
          
  • Expression evaluation. Converting 3 + 4 * 2 to postfix and evaluating it uses a stack of operators and one of operands.
    • 
          
  • Depth-first search and backtracking (maze solving, sudoku solvers).
    • 
          
  • Reversing anything: push every character of a string, then pop them all.
    • 
        

      

      
Why the bracket checker works: the most recently opened bracket must be the first one closed. That is exactly LIFO order, so when a closer arrives, the opener it must match is always on top of the stack.

    

  







  

    
FIFO · First in, first out

    
Queue

    
A queue works like a line at a ticket counter. New arrivals join at the rear (enqueue) and service happens at the front (dequeue), so items leave in the order they arrived.

  


  

    

      

      

        
        
        
      

      
      
This queue is a circular array of 8 slots. Enqueue a few values and watch rear wrap from index 7 back to 0.

    

    

      

      

    

    

  


  

    

      
How a queue works

      

        

          
A queue keeps two ends: the front, where items leave, and the rear, where items join. That gives FIFO order (first in, first out). Nobody cuts the line.

          
The naive array problem. If you store the queue in an array and always keep the front at index 0, every dequeue has to shift all remaining items left by one. That makes dequeue O(n). If instead you just move a front index forward, the slots behind it are wasted forever.

        

        

          
The fix: a circular buffer. Treat the array as a ring. Both indices move forward with (index + 1) % capacity, so after the last slot they wrap back to slot 0 and reuse the space freed by earlier dequeues. Nothing is ever shifted, so both operations are O(1).

          
Full or empty? In a ring, a full queue and an empty one can leave front and rear in the same relative positions. The demo keeps a separate count to tell them apart. (Another common trick is to always leave one slot unused.)

Variants and uses

      

        
    
          
  • Deque (double-ended queue): add and remove at both ends. Python's collections.deque, Java's ArrayDeque.
    • 
          
  • Priority queue: the item with the highest priority leaves first, not the oldest. Usually built on a binary heap with O(log n) operations.
    • 
          
  • Ring buffer: a fixed-size circular queue that overwrites the oldest data when full. Common in audio, logging and network drivers.
    • 
        

        
    
          
  • Breadth-first search: visit a graph level by level by queueing neighbours.
    • 
          
  • Scheduling: print jobs, CPU round-robin, customer support tickets.
    • 
          
  • Buffers between producers and consumers: keyboard input, message queues such as RabbitMQ or Kafka, video streaming.
    • 
        

      

    

  







  

    
Key → hash → index

    
Hash Table

    
A hash table stores key–value pairs and finds them almost instantly. A hash function turns the key into an array index, so instead of searching you jump straight to the right bucket.

  


  

    

      

      

      

        
        
        
      

      
      
Collision strategy
        

          
          
        

      

      
      
The table has 7 buckets. apple and mango already collide in bucket 5. Try putting listen and then silent: anagrams always collide with this hash function.

    

    

      

      

    

    

  


  

    

      
How a hash table works

      

        

          
Searching an unsorted list means checking items one by one: O(n). A hash table avoids that by computing where a key should live. Every operation follows the same two steps:

          
    
            
  1. Hash the key into a number: h = hash(key).
    2. 
            
  2. Compress it into a valid index: i = h mod size. Then look only in bucket i.
    3. 
          

          
If keys spread evenly, each bucket holds about one item, so put, get and remove take O(1) on average.

        

        

          
What makes a good hash function

          
    
            
  • Deterministic: the same key always gives the same number.
    • 
            
  • Uniform: keys spread evenly across buckets.
    • 
            
  • Fast to compute.
    • 
          

          
This demo adds up character codes because you can follow the arithmetic by hand. It is a weak hash: any two words with the same letters (listen, silent) collide. Real string hashes weight each position, e.g. Java's s[0]·31n-1 + s[1]·31n-2 + …. Table sizes are often prime (like 7 here) so patterns in the hash values don't all pile into the same few buckets.

        

      

    

    

      
Collisions: two keys, one index

      
With more possible keys than buckets, collisions are guaranteed. There are two main ways to handle them, and the toggle above switches between them:

      

        

          
Separate chaining

          
Each bucket holds a linked list. Colliding keys are appended to the list. Lookups hash to the bucket, then walk the chain comparing keys. Simple, and the table never "fills up", but long chains slow it down.

        

        

          
Open addressing (linear probing)

          
Every slot holds at most one entry. On a collision, try the next slot: i = (i + 1) mod size, until an empty one appears. Cache-friendly, but neighbouring entries clump into clusters that make probes longer. Quadratic probing and double hashing spread entries out to reduce clustering.

        

      

      
Why removal leaves a tombstone: with probing, a lookup stops at the first EMPTY slot. If remove simply emptied a slot, any key that had probed past it would become unreachable. A DELETED marker says "something used to be here, keep looking". Try it: remove kiwi in probing mode, then get fig.

    

    

      
Load factor and resizing

      
The load factor is α = entries / buckets. As α grows, chains get longer and probe runs get longer. Real implementations resize once α crosses a threshold (Java's HashMap uses 0.75; Python's dict about 2/3): they allocate a bigger array and re-insert every entry, because each key's index depends on the table size. That one rehash is O(n), but it happens rarely, so the average cost per insert stays O(1).

Hash tables power Python's dict and set, JavaScript's Map and objects, Java's HashMap, caches, database indexes, compilers' symbol tables, and every "count how many times each word appears" program.

How the algorithms compare

      
The highlighted card is the algorithm loaded above. Watch the comparisons and swaps / writes counters in the stage: they are the real cost of each algorithm on that exact input.

      

        
Bubble sort O(n²)

          
Walk through the array comparing neighbours and swap any pair that is out of order. After each pass the largest remaining value has "bubbled" to the end. Stops early if a pass makes no swaps.

          
best O(n)worst O(n²)space O(1)stable

        
Selection sort O(n²)

          
Scan the unsorted part for its minimum and swap it to the front of that part. Always does about n²/2 comparisons, but at most n − 1 swaps, which helps when writes are expensive.

          
best O(n²)worst O(n²)space O(1)not stable

        
Insertion sort O(n²)

          
Grow a sorted prefix one value at a time: lift out the next value (the key), shift bigger values right, drop the key into the gap. Very fast on small or nearly sorted inputs, which is why real libraries use it for short runs.

          
best O(n)worst O(n²)space O(1)stable

        
Merge sort O(n log n)

          
Divide and conquer: split the array in half, sort each half recursively, then merge the two sorted halves by repeatedly taking the smaller front value. Guaranteed n log n, at the cost of a temporary array.

          
best O(n log n)worst O(n log n)space O(n)stable

        
Quick sort O(n log n) avg

          
Pick a pivot (here: the last element) and partition so smaller values go left and the rest go right. The pivot lands in its final position; recurse on each side. Usually the fastest in practice, but a bad pivot on already sorted or reversed input degrades it to O(n²).

          
best O(n log n)worst O(n²)space O(log n)not stable

Terms worth knowing

      

        
    
          
  • Stable: equal values keep their original relative order. Matters when you sort records by one field after another (sort by name, then stably by grade).
    • 
          
  • In-place: needs only a constant amount of extra memory beyond the array.
    • 
          
  • Adaptive: runs faster when the input is already partly sorted (bubble with early exit, insertion).
    • 
        

        
    
          
  • The n log n barrier: any sort that works only by comparing pairs needs at least about n log₂ n comparisons in the worst case. Merge sort reaches that bound.
    • 
          
  • What real libraries use: Python and Java (for objects) use Timsort, a merge/insertion hybrid. C++ std::sort uses introsort: quick sort that falls back to heap sort and finishes small ranges with insertion sort.
    • 
        

      

      
Experiments to try: pick Nearly sorted and compare insertion sort with selection sort. Then pick Reversed with quick sort and watch every partition peel off just one element: that's the O(n²) worst case.
